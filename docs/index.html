Weekly Map

Course topic overview

The course moves from core computing skills into complete workflows for genomics, transcriptomics, chromatin accessibility, single-cell analysis, microbiome and metagenomics, and a final reproduction project.

  1. Week 0Shell navigation and Python or R preparation.
  2. Week 1Command line, Git, HPC, conda/mamba, containers, and public data.
  3. Week 2Sequencing technologies, experimental design, FASTQ QC, fastp, and MultiQC.
  4. Week 3Genome assembly, annotation, assembly QC, GFF3/GTF, and IGV.
  5. Week 4Alignment, SAM/BAM, variant calling, benchmarking, annotation, and VCFs.
  6. Week 5Bulk RNA-seq quantification, nf-core/rnaseq, counts, metadata, and exploration.
  7. Week 6DESeq2, covariates, multiple testing, visualization, enrichment, and reporting.
  8. Week 7ATAC-seq, peak calling, nf-core/atacseq, QC, motifs, and expression integration.
  9. Week 8Single-cell reads to cells, Cell Ranger, STARsolo, alevin-fry, AnnData, and Seurat.
  10. Week 9Clustering, cell type annotation, integration, pseudobulk testing, and spatial data.
  11. Week 1016S, QIIME2/DADA2, compositional data, shotgun profiling, MAGs, and diversity.
  12. Weeks 12-14Mini-project reproduction work, reports, repositories, and presentations.

Working Standards

What good course work should leave behind

Reproducibility

Keep commands, versions, sample IDs, parameters, input sources, small config files, and expected outputs visible.

Git and GitHub

Pull before class, commit your own work clearly, and organize final project repositories so another group could rerun the analysis.

HPC

Use login nodes for light work, submit compute jobs through the scheduler, and follow course guidance for storage and job scripts.

Environments

Prefer conda or mamba environment files and record any package changes needed for an assignment or project.

Containers

Record image names, tags, bind mounts, and runtime options so a workflow can be rerun with the same assumptions.

Nextflow and nf-core

Preserve sample sheets, parameter files, configuration files, logs, and reports from workflow runs.

Notebooks

Make notebooks run from top to bottom, explain major choices, label outputs, and interpret results rather than only showing code.

Critical Evaluation

Treat successful execution as the start of interpretation, not proof that the result is correct.

Responsible AI Use

Use assistants, then verify the science

  • Disclose AI use in submitted notebooks or reports.
  • Verify generated commands, code, and explanations.
  • You are responsible for every line you submit.
  • Keep interpretation, discussion, and limitations in your own scientific voice.
